# ADR 0011 — Drizzle for queries, SQL as the schema source of truth

- **Status:** Accepted
- **Date:** 2026-06-22

## Context
We want Drizzle's typed queries and large agent corpus, but integrity lives in raw SQL (ADR 0003).
Drizzle's default "schema-as-TypeScript with generated migrations" would create a second source of
schema truth that can drift from the hand-written SQL.

## Decision
Raw SQL migrations (dbmate) are the single source of schema truth. The Drizzle schema
(`apps/web/app/db/schema.ts`) is **generated by `drizzle-kit introspect`** from the migrated
database and is never hand-edited (a hook blocks edits to it).

## Consequences
- No schema drift; SQL is authoritative, types follow.
- A regeneration step (`pnpm db:introspect`) after every migration.

## Alternatives considered
- **Drizzle schema-first** — rejected: two sources of truth for a ledger schema.
- **Kysely** (no schema-as-code at all) — viable and more SQL-honest, but Drizzle's corpus/DX wins
  for an agent build once the introspection workflow removes the drift concern.
